# TI 2026 Predictor — Railway + PostgreSQL + ручное закрытие прогнозов

Эта версия хранит всё в PostgreSQL и позволяет админу вручную открывать и закрывать прогнозы.

## Что изменилось

Админские команды:

```text
/open
```

Открывает прогнозы.

```text
/close
```

Закрывает прогнозы.

```text
/status
```

Показывает, открыты они сейчас или закрыты.

После `/close` пользователь не сможет:
- начать новый прогноз;
- продолжить незавершённый прогноз;
- нажать старую кнопку выбора, оставшуюся в Telegram.

При этом продолжают работать:
- `/score`;
- `/leaderboard`;
- уже полностью заполненные прогнозы;
- админский ввод реальных результатов через `/admin`.

Закрытие происходит ТОЛЬКО вручную.
Внесение реального результата никак не закрывает прогнозы автоматически.

Состояние OPEN/CLOSED хранится в PostgreSQL, поэтому после перезапуска Railway оно не сбрасывается.

# Установка с телефона

## 1. Создай Telegram-бота

Открой в Telegram:

```text
@BotFather
```

Отправь:

```text
/newbot
```

Задай имя и username.

BotFather выдаст токен вида:

```text
123456789:AA......
```

Это `BOT_TOKEN`.

Никому его не отправляй.

---

## 2. Узнай свой Telegram ID

Можно использовать любого Telegram ID-бота.

Либо сначала запустить нашего бота с:

```text
ADMIN_IDS=0
```

и затем написать ему:

```text
/admin
```

Он покажет твой Telegram ID.

---

## 3. Создай GitHub-репозиторий

На github.com:

1. Нажми `New repository`.
2. Назови, например:

```text
ti-predictor
```

3. Создай репозиторий.
4. Загрузи в корень все файлы из этого ZIP:

```text
bot.py
requirements.txt
railway.json
README.md
.gitignore
```

Важно: `bot.py` должен лежать прямо в корне репозитория, а не во вложенной папке.

---

## 4. Создай Railway Project

На railway.com:

1. `New Project`
2. `Deploy from GitHub repo`
3. Выбери репозиторий `ti-predictor`.

Railway создаст сервис бота.

---

## 5. Добавь PostgreSQL

Внутри того же Railway Project:

1. Нажми `+ New`
2. Выбери `Database`
3. Выбери `PostgreSQL`

Появится отдельный Postgres-сервис.

---

## 6. Добавь переменные

Открой сервис БОТА, не PostgreSQL.

Перейди:

```text
Variables
```

Добавь:

```text
BOT_TOKEN=токен_от_BotFather
```

```text
ADMIN_IDS=твой_telegram_id
```

```text
DATABASE_URL=${{Postgres.DATABASE_URL}}
```

Если PostgreSQL-сервис у тебя называется не `Postgres`, используй его фактическое имя.

После изменения Variables Railway обычно делает redeploy.

---

## 7. Запуск

Команда уже записана в `railway.json`:

```text
python bot.py
```

После успешного Deploy открой своего Telegram-бота и напиши:

```text
/start
```

# Как пользоваться

## До начала турнира

Открой прогнозы:

```text
/open
```

Проверь:

```text
/status
```

Ответ:

```text
🟢 Прогнозы сейчас ОТКРЫТЫ.
```

Отправляешь ссылку на бота людям.

Они проходят сетку.

---

## В момент дедлайна

Пишешь:

```text
/close
```

Бот ответит:

```text
🔒 Приём прогнозов закрыт.
Никто больше не сможет начать или продолжить заполнение прогноза.
```

Проверь:

```text
/status
```

Ответ:

```text
🔴 Прогнозы сейчас ЗАКРЫТЫ.
```

Теперь даже старые кнопки выбора у пользователей не сработают.

---

## Если надо снова открыть

```text
/open
```

Все незавершённые прогнозы снова смогут продолжиться.

---

# Внесение реальных результатов

Пишешь:

```text
/admin
```

Бот покажет очередную реальную пару.

Нажимаешь команду, которая реально победила.

После этого:
- результат сохраняется;
- сетка реальных матчей перестраивается;
- всем участникам пересчитывается счёт;
- бот отправляет им уведомление.

---

# Если ошибся с реальным результатом

Например:

```text
/undoresult UB5
```

Будет удалён UB5 и зависимые результаты после него.

Затем снова вводишь правильные результаты через:

```text
/admin
```

---

# Команды

Для всех:

```text
/start
/score
/leaderboard
```

Только для админа:

```text
/admin
/open
/close
/status
/undoresult UB1
```

---

# Важный сценарий

Лучший порядок действий:

1. `/open`
2. дать людям ссылку;
3. дождаться дедлайна;
4. `/close`
5. `/status`
6. после матчей `/admin`
7. вносить реальные результаты;
8. смотреть `/leaderboard`.
